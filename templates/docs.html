Getting started

HiveBots hosts Telegram bots for you. You write small scripts called commands; HiveBots handles the server, the webhook, and the uptime.

  1. Create a free account.
  2. Open Telegram, message @BotFather, and send /newbot.
  3. Copy the API token BotFather gives you.
  4. On your HiveBots dashboard, click Add new bot and paste the token.
  5. Edit the auto-created /start command, then press Start bot.

Scripting reference (HiveScript)

HiveScript is a restricted Python dialect. If you can write basic Python, you can write HiveScript. Each command's code runs inside its own sandbox with a fixed set of safe built-ins (len, str, range, json, math, random, re, and similar) — file access, network access, and imports outside that list are not available.

# /start
first_name = message.from_user.first_name
bot.sendMessage(f"Hey {first_name}! Welcome 👋\n\nUse /help to see what I can do.")

# /help
bot.sendMessage("""Available commands:
/start - Welcome message
/help - This menu""")

Sending messages

  • bot.sendMessage(text, buttons=None, parse_mode="HTML") — send text, optionally with inline buttons.
  • bot.sendPhoto(url, caption=None, buttons=None) — send an image by URL.
  • bot.sendDocument(url, caption=None) — send a file by URL.
  • bot.sendChatAction("typing") — show a "typing…" indicator.
bot.sendMessage(
    "Choose an option:",
    buttons=[[("Pricing", "show_pricing"), ("Support", "show_support")]]
)

Buttons

buttons is a list of rows; each row is a list of (label, target) pairs. If target starts with http, it opens a link — otherwise it's sent back to your bot as a callback you can route to a command.

Context variables

Every command automatically has access to these, with no setup:

bot / Bot

Send messages, broadcast, and schedule follow-ups for the current chat.

message / msg

.text, .chat.id, and .from_user.first_name / .username / .id.

params

Everything typed after the command. /refer 882 → params == "882".

User

.saveData(key, value) / .getData(key, default) — persistent storage per Telegram user, scoped to this bot.

Account

Read-only info about the bot itself: .bot_name, .bot_username, .owner_email.

options

A scratch dictionary available for advanced use within a single execution.

Flow control

Waiting for the next message

bot.handleNextCommand(trigger) tells HiveBots to route the user's very next message — whatever it says — to a specific command, instead of matching it normally. Perfect for "what's your name?" style prompts.

# /ask_name
bot.sendMessage("What should I call you?")
bot.handleNextCommand("/save_name")

# /save_name
name = params  # the user's reply lands here
User.saveData("name", name)
bot.sendMessage(f"Nice to meet you, {name}!")

Wildcard commands

A command with the trigger * catches any message that doesn't match a real command — handy for fallback replies or free-text menus.

Scheduling

bot.runCommandAfter(seconds, trigger) re-invokes a command after a delay, for the current user by default.

bot.sendMessage("I'll remind you in 1 hour.")
bot.runCommandAfter(3600, "/reminder")

Broadcasting

bot.broadcast(text, buttons=None) messages every user who has ever written to your bot. You can also trigger a broadcast without code from the Broadcast tab on any bot.

How hosting works

When you press Start bot, HiveBots registers a webhook with Telegram pointing at your deployment's /webhook/<bot_id>/<secret> endpoint. From then on, Telegram pushes updates to that URL the moment they happen — no polling loop running in the background. Stopping a bot removes the webhook.

Because this is a self-hosted Flask app, your webhook URL is only reachable if your deployment has a public HTTPS address. Local development needs a tunnel (e.g. ngrok) for Telegram to reach it.

Points & limits

Every account gets 100,000 free execution points each calendar month. Each command run costs 1 point. There's no limit on the number of bots or commands you can create — only on total executions per month. The deployment owner can adjust this cap directly in the database.

FAQ

My bot isn't responding

Check the Error logs tab first — most issues are a syntax error or an exception in your command code. Also confirm the bot shows as Live on Settings.

Can I use one token for two bots?

No — Telegram allows one webhook per token. Cloning a bot copies its commands but you'll need to attach a fresh token before starting the clone.

Is my code really sandboxed?

Commands run with a restricted set of built-ins and no filesystem or arbitrary network access. This is meant to stop accidental damage, not to be a hard security boundary — don't run untrusted third-party commands on a production deployment without additional isolation (e.g. a subprocess sandbox or containers).
